# T425-SIM HOSTIO Integration with the Original INMOS IServer 1.50v

## Status

F245 demonstrated a functional integration in an isolated variant. It is not yet a reproducible release on the current canonical revision. No CORE, CROM, MIR, scheduler, CHANNEL, or PHY change was made for this integration.

## Architecture

The CORE continues to execute instructions through `OPR → CROM → MIR → microsequencer → datapath`. The VM owns one session containing the CORE, executor, transport, and host adapter bound to endpoint `T425SIM0`. The original INMOS IServer receives normal `argc/argv`, constructs command lines through `MakeCommandLine`/`ParseCommandLine`, runs `Boot → Serve`, and owns HOSTIO dispatch and file handlers.

In the experimental F244/F245 runner, the guest/IServer boundary transports ordered bytes. `OPS_GetRequest`, `Serve`, original handlers such as `SpOpen`/`SpSeek`, and `OPS_SendReply` remain active. The F240 service peer does not answer requests. The experimental runner still uses host TX/ACK callbacks for virtual PHY operation; this does not validate the physical PHY.

## SP_ID profile

The 1.50v IServer returns the profile generated by original `SpId`: frame `06 00 00 0F 00 00 00 00`. The F240 reference run advertised the compatibility profile `05 00 00 0E 01 01 01`. An isolated F245 intervention showed that selecting this profile changes ILINK's path and allows it to reach the `test04.cah` output open.

A release integration should expose two named host-side profiles: `inmos-1.50` (default, no rewrite) and `compat-v14` (profile validated by F245). `compat-v14` is not a CORE correction and does not claim the original profile is wrong for other targets.

## Limitations and gates

- F245 ran an isolated variant derived from the F240/F212 snapshot. A reproducible build from the current canonical tree failed because the F245 trace/test references CORE fields and `t425_byte_write.c` that are absent from this base. Those deltas must not be imported as HOSTIO integration work.
- `compat-v14` was validated for T04–T06, not as a universal profile for every program or target.
- The result uses virtual PHY and host callbacks; it does not validate RP2040 or physical ACK behavior.
- No commit, push, or deploy was made. Release remains gated on base reconciliation and a clean build.
